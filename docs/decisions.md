# Decisions

Each row is dated and written when the decision is made.

| # | Kind | Decision | Why | Alternatives considered | Consequence |
|---|---|---|---|---|---|
| D1 | product | 2026-10-28. Cron runs one `ingest_feeds` pass each 15 min. The pass exits when done. | A one-shot command needs no in-process timer, restart logic or health check. | A long-running worker with its own timer: more ops for the same result. | A Postgres advisory lock must stop two passes at once. |
| D2 | product | 2026-10-28. Store one article per canonical URL. Same story on two URLs stays two rows. | Same-story matching needs an LLM or a similarity score. That is not the `mvp` bet. | Title similarity dedup: false merges on short titles like "GPT-6 is out". | A consumer can see the same story twice from two sources. |
| D3 | product | 2026-10-28. Metric: 95% of articles stored under 30 min after `published_at`. 0 duplicate canonical URLs. (assumed) | Both values come from one query on the article table. | Count of articles per day: it grows with feeds, not with quality. | A feed with wrong `published_at` values moves the metric. Exclude it in the query. |
| D4 | product | 2026-10-28. The user is the owner of an AI news digest. (assumed) | No other role reads the store at `mvp`. | Downstream services as the user: none exists yet. | The stop condition reads the metric only. |
| D5 | product | 2026-10-28. Feeds live in a `Feed` table, edited in Django admin. | Django admin gives the edit screen with no build work. | A config file in the repo: each new feed needs a deploy. | The pass reads active `Feed` rows at its start. |
| D6 | tech | 2026-10-28. Python, Django and Postgres. | Owner choice. | TypeScript on Node. | Django ORM and admin are adapters, never domain code. |
| D7 | tech | 2026-10-28. Hexagonal architecture. The domain imports no Django, no feedparser and no HTTP. | Domain rules get tests with no database or network. | Django apps with logic in models and views: tests need the database. | One mapping per ORM model. An `import-linter` contract fails CI on a wrong import. |
| D8 | tech | 2026-10-28. `feedparser` reads RSS and Atom. `import-linter` checks the layers. | Both checked on PyPI: maintained since 2007 and 2019, source repos public. | Own XML parser: many feed format edge cases. | `feedparser` lives in the FeedReader adapter only. |
| D9 | product | 2026-10-28. The first stored copy of a canonical URL wins. A later copy never updates it. | One write per URL keeps the store append-only and the unique key simple. | Last copy wins: a slow mirror feed can overwrite the original title. | A feed that fixes a typo in a title later is not seen. |
| D10 | product | 2026-10-28. A skipped tick writes a log line only, no run record. | A skip changes no data. | A run record per skip: rows with zero counts that hide real passes. | A long overrun shows only in logs and in the gap between run records. |
| D11 | product | 2026-10-28. The canonical URL keeps other query parameters in their given order. | Some sites use parameter order. A sort can merge two different pages. | Sort parameters: catches more duplicates on rare feeds that reorder. | The same page with reordered parameters is stored twice. |
| D12 | product | 2026-10-28. A skipped tick exits with code 0. | Cron mails the owner on a non-zero exit. A skip is normal. | Exit code 75: cron mails on each overrun. | An overrun shows in logs only (D10). |
| D13 | product | 2026-10-28. The pass reads the active feed list once, at its start. | One read gives one clear rule for the whole pass. | Check active before each feed: one query per feed, and a pass with a moving list. | A feed turned off mid-pass is read one more time. |
| D14 | product | 2026-10-28. **Q1, S1 AC5.** A feed URL is unique, compared exactly. | Two rows for one feed double the fetches each pass. | Unique on the canonical feed URL: one more rule for a rare mistake. | `https://Example.com/feed` and `https://example.com/feed` can both exist. |
| D15 | product | 2026-10-28. **Q2, S8 AC1-AC2.** A feed with stored articles cannot be deleted. The owner turns it off instead. | The metric and the article history stay complete. | Cascade: deletes history and changes past metric values. Set null: articles with no source. | A dead feed stays as an inactive row in the admin list. |
| D16 | product | 2026-10-28. **Q3, S5 AC7-AC9.** Each feed keeps `last_status`, `last_read_at` and `failing_since`. The admin list shows failing feeds first. | The owner must see which feed is broken. Run records give counts only. | A per-feed result table each pass: 96 rows per feed per day for one fact. Alerts: cut at `mvp`. | ReadFeed writes the feed health fields after each read. |
| D17 | product | 2026-10-28. **Q4, S6 AC9, S9 AC1.** An item with no published date is stored. The metric excludes it and prints the excluded count. | The owner still gets the news. The metric stays true. | Reject the item: real news lost. Use `stored_at`: each such row counts as on time. | Over 5% excluded makes the metric invalid. |
| D18 | product | 2026-10-28. **Q5, S6 AC10, S9 AC2.** A future published date is stored as given. The metric excludes dates over 5 min after `stored_at`. | A stored fact stays as the feed gave it. 5 min covers clock skew. | Clamp to the fetch time: a false date in the store. | Future dates show in the excluded count. |
| D19 | product | 2026-10-28. **Q6, S6 AC11.** The canonical URL drops `utm_*`, `fbclid`, `gclid`, `mc_cid` and `mc_eid`. Other parameters stay. | These five never change the page. `ref` and others can. | `utm_*` only: social links stay duplicated. Drop all parameters: merges different pages. | A new tracker needs a code change. |
| D20 | tech | 2026-10-28. **H8, S5 AC10-AC11.** A feed read has a 10 s total deadline and a 5 MB body cap. | A slow drip passes a per-read timeout. 20 feeds x 10 s = 200 s, under 15 min. | Per-read timeout only: one drip feed can hold the pass for minutes. | A large real feed over 5 MB fails as `too_large`. |
| D21 | tech | 2026-10-28. **H7, S7 AC2.** The articles of one feed commit in one transaction. A run record with no finished time reads as unfinished. | A crash loses one feed batch at most. The next tick repeats it with no duplicate. | One transaction per article: 20x more commits. One per pass: a crash loses all. | A crash leaves an unfinished run record, derived on read. |
| D22 | tech | 2026-10-28. One Django app `ingest` with `domain`, `application` and `adapters` folders. One aggregate: Feed. Policies P2-P4 are in-process calls. | One context, one owner, one language. No async step needs an outbox. | One Django app per layer: three apps for one context. A broker: no second service. | `import-linter` checks the folder rule. |
